# BOSS 人选重复统计 v1.15.5

## 人选重复统计

1. 在 Chrome 扩展管理页面加载本文件夹。
2. 完整刷新或重新打开 BOSS 页面。
3. 点击插件图标，填写同事姓名并点击“开始统计”。
4. 正常手动查看候选人；没有打开详情时不会计数。
5. 完成后点击“结束并生成报告”。
6. 结束后，记录直接显示在“当前统计”页面下方的“查重记录”区域，可单条删除或清空。

## 招聘数据日终采集

1. 人工登录 BOSS，人工进入“招聘数据—日报”。
2. 人工选择需要记录的岗位，等待页面数字加载完成。
3. 打开插件，进入“招聘日报”，点击“读取当前日报”。
4. 核对日期、岗位、Base、BOSS 指标及可匹配的重复统计预览。
5. 确认无误后点击“保存记录”。如果发现日期、岗位和 Base 均相同的重复统计，插件会询问是否合并；同一日报再次保存时会询问是否覆盖。
6. 保存的数据可在“招聘日报历史”中查看和单条删除。

## 同步到钉钉 AI 表格

1. 在“招聘日报”中展开“钉钉 AI 表格同步设置”。
2. 粘贴 `https://connector.dingtalk.com/webhook/flow/...` 格式的自动化工作流 Webhook 并保存。地址单独保存在本机，不会写进插件源码，也不会发送给 BOSS。
3. 完成日报与查重数据合并后，在历史表格对应行点击“同步”。未合并查重数据的记录不会同步，避免向钉钉写入不完整数据。
4. 成功、失败和最后同步时间会显示在记录旁。已同步记录可以使用相同同步键重新发送。

保存成功后，设置区会显示“Webhook 地址已保存”，以后无需再次粘贴。更新未打包扩展时应保留原扩展和原文件夹路径、替换文件后点击“重新加载”；如果先删除扩展或改用另一个解压路径，Chrome 会把它视为另一份扩展，本地配置也会随之隔离。

发送到工作流的 JSON 字段为：`eventType`、`date`、`jobName`、`baseCity`、`viewCount`、`duplicateCount`、`greetCount`、`viewMeCount`、`newGreetCount`、`communicationCount`、`contactCount`、`syncKey`。

`syncKey` 使用 `日期_Base_岗位名称`。工作流应依据该字段执行新增或更新，以避免重复行。插件不会写入钉钉表格中的公式列。

无法从页面明确读到的字段会显示“读取失败 / null”，不会自动写成 0。保存前需要重新读取当前页面，且存在缺失字段时不会落库。

## 本地数据

业务数据保存在 `chrome.storage.local` 的 `bossDupStateV1` 中。日报记录同步后会增加 `dingTalkSync` 状态。Webhook 单独保存在 `bossDupDingTalkConfigV1`，不会进入业务状态或内容脚本。原有结构包括：

- `recruitDraft`：最近一次日报页面解析草稿；
- `recruitDailyHistory`：人工确认保存的招聘日报记录。

旧版本的 `settings`、`session`、`candidates`、`history` 和 `current` 会原样兼容。

## 架构与边界

- 后台服务统一管理 Session、候选人去重、日报历史和本地存储，所有写入串行执行。
- 外层页面显示悬浮统计面板，并只读解析当前招聘日报 DOM。
- 候选人 iframe 只识别当前候选人和沟通记录，通过消息上报，不直接访问本地存储。
- 页面切换时旧识别任务自动作废，旧结果不能覆盖当前候选人。

插件不自动登录、点击、切换岗位、滚动、翻页或打招呼，不使用 OCR，不调用隐藏接口，也不上传数据。
